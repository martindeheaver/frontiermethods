01 / Research thesis

Intelligence may be a property of the system, not just the model.

What changes when a community of local AI systems can access a shared, continuously maintained representation of the world?

Today's AI architectures often separate device-level intelligence, cloud inference and communications infrastructure. Frontier Methods explores an alternative: design the model, compute substrate and network as a coordinated system, so that local agents can collaborate without sending every task to a remote, general-purpose service.

This is a research proposition, not a claim that a complete architecture already exists. The goal is to identify where shared context creates measurable advantages—and what hardware, protocols and governance it requires.

02 / System architecture

Three interacting layers.

The design space spans model representation, runtime placement and the communication fabric. Optimising one layer in isolation may simply move the bottleneck elsewhere.

03 / Research agenda

Questions before claims.

The agenda is organised around falsifiable questions and measurable systems outcomes—not a predetermined technology stack.

RQ 01 / REPRESENTATION

What should the shared world model contain?

Which information belongs in stable model parameters, dynamic shared state, local private context or transient messages? How can compact representations preserve task-relevant meaning?

RQ 02 / CONSISTENCY

How does a distributed community maintain coherent state?

Investigate update propagation, provenance, conflict resolution, stale context and operation through partitions or intermittent connectivity.

RQ 03 / INFERENCE

Where should each task run?

Develop placement policies that balance response time, energy, privacy, model capability, network load and shared-resource availability.

RQ 04 / SILICON

What deserves a dedicated accelerator?

Profile the workload before fixing the hardware. Explore memory hierarchy, data movement, precision, throughput and deterministic latency for candidate operations.

RQ 05 / NETWORK

What communications fabric does cooperation require?

Quantify message size, fan-out, burstiness and latency budgets; test scheduling, routing and graceful degradation under constrained bandwidth.

RQ 06 / TRUST

Who controls shared intelligence?

Address identity, consent, permissions, data minimisation, malicious updates, auditability and the ability to leave or reconfigure a community.

04 / Technical workstreams

From first principles to prototypes.

A staged programme can reduce uncertainty early and make each research investment answer a concrete question.

WORKSTREAM 01

Model and state decomposition

Define the boundary between fixed weights, community state, local memory and messages. Establish candidate data structures and update semantics.

WORKSTREAM 02

Distributed runtime

Build a simulator to compare local-only, cloud-mediated and community-assisted inference under repeatable workload and network conditions.

WORKSTREAM 03

Hardware workload study

Profile operations, memory traffic and latency targets before deciding whether an ASIC or another accelerator is justified.

WORKSTREAM 04

Network co-design

Derive communication requirements from measured inference workloads, then evaluate radio, routing and medium-access trade-offs.

WORKSTREAM 05

Security and governance

Threat-model node compromise, poisoned updates, privacy leakage and resource abuse. Treat trust as a system property.

WORKSTREAM 06

Benchmarks and evidence

Publish baselines, assumptions and reproducible measurements for latency, bandwidth, energy, availability and task quality.

05 / Research method

Make the architecture earn its complexity.

A credible path begins with a baseline, isolates the value of shared context, then adds specialised hardware or network novelty only where evidence supports it.

STEP 01

Specify

Define workloads, community assumptions, threat model and success metrics.

STEP 02

Simulate

Compare architectures under controlled latency, bandwidth and failure conditions.

STEP 03

Prototype

Build the smallest end-to-end system that can test the core hypotheses.

STEP 04

Measure

Publish results, limitations and negative findings; revise the design accordingly.

Near-term investigation

Workload and systems research

Model decomposition, distributed runtime simulation, message budgets, baseline comparisons and threat modelling are tractable first steps with clear evaluation criteria.

Longer-term horizon

Emerging radio technologies

Rydberg-atom receivers and other unconventional approaches may merit monitoring as research into broadband reception and sensing advances. Their suitability for low-power, high-bandwidth community networking remains an open experimental question.
